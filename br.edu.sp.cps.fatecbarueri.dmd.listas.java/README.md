# br.edu.sp.cps.fatecbarueri.dmd.listas.java

Soluções das Listas de Exercícios de Java (Listas 1 a 5) - FATEC Barueri, Design de Mídias Digitais.

Projeto Eclipse pronto para importar. Código compatível com Java 11 ou superior, sem bibliotecas externas.

## Como importar no Eclipse

1. Descompacte o `.zip` (se for o caso).
2. No Eclipse: **File > Import > General > Existing Projects into Workspace**.
3. Em *Select root directory*, escolha a pasta `br.edu.sp.cps.fatecbarueri.dmd.listas.java` e clique em **Finish**.

## Como executar um exercício

1. No *Package Explorer*, abra `src` e o pacote do exercício desejado (veja a tabela abaixo).
2. Clique com o botão direito na classe `Main` do pacote e escolha **Run As > Java Application**.
3. Nos exercícios que leem dados, digite no console do Eclipse (aba *Console*) e pressione Enter.
   Os exercícios da Lista 1 não pedem digitação: usam dados fixos e mostram a saída direto.

## Estrutura

Cada exercício fica em seu próprio pacote, no padrão `br.edu.sp.cps.fatecbarueri.dmd.listas.java.listaNN.exercicioNN.assunto`, com uma classe
`Main` (que executa o exercício) e as classes de apoio. Nenhuma classe é compartilhada entre pacotes de
exercícios diferentes, então cada pasta pode ser aberta ou entregue separadamente.

## Perguntas para reflexão (Lista 5)

**1. Por que dividir em funções deixa o código melhor?**

Dividir em funções deixa o código mais organizado, mais fácil de entender e mais fácil de corrigir. Quando cada função tem uma responsabilidade, conseguimos identificar melhor onde está cada parte da lógica.

Exemplo: `calcularMedia()`, `verificarSituacao()` e `mostrarResultado()`. Cada função faz uma coisa específica.

**2. O que acontece quando colocamos tudo no main?**

O `main` fica grande, confuso e difícil de manter. Quando tudo fica no `main`, o programa pode ter:

- código repetido;
- dificuldade para encontrar erros;
- mistura de várias responsabilidades;
- menor reaproveitamento;
- mais dificuldade para evoluir o sistema.

O ideal é que o `main` apenas organize o fluxo do programa.

**3. Como escolher um bom nome para uma função?**

Um bom nome de função deve explicar claramente o que ela faz. Bons exemplos: `calcularMedia()`, `mostrarMenu()`, `lerNumero()`, `validarSenha()`, `sortearNumero()`, `verificarVencedor()`. Nomes ruins: `fazer()`, `coisa()`, `teste()`, `executar()`, `metodo1()`.

A função deve começar, de preferência, com um verbo, porque representa uma ação. Exemplos: `calcular`, `mostrar`, `ler`, `validar`, `verificar`, `sortear`, `exibir`.

> Regra final: o objetivo não é apenas fazer o programa funcionar, e sim fazê-lo funcionar com organização. Um bom programa é dividido em partes pequenas, com nomes claros e responsabilidades bem definidas.
